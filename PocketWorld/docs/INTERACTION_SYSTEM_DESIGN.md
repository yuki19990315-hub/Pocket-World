# サンニー v0.4 操作・表示・通信の統合設計

状態: **設計案 / 丸形LCDへの描画・本体タッチは未実装 / スマホ側の一部はv0.3で実装済**  
更新: 2026-11-18（日本時間）

関連: [生活サイクル・電池・外装](LIFE_CYCLE_POWER_ENCLOSURE.md)

## 1. 基本原則

- ESP32「サンニー」が**6世界の唯一の正規データ**を持ち、スマホは観察・操作・設定を送るクライアント。
- 本体とスマホは**別々の世界を表示できる**。スマホ画面のタブ操作では、本体の景色を勝手に変えない。
- スマホ上の「サンニーに表示」でのみ本体の表示世界を変更する。サンニーのタッチ操作による切り替えも可能にする。
- スリープ・保存・電池警告などは全モードに共通する基盤として実装し、各モードが重複した処理を持たない。
- ジャイロ・加速度センサーは本体の動きと世界の演出を結ぶ**標準機能として採用**。マイクは音量レベルに応じて変化する**任意の拡張**。機材が未接続でもすべての世界が正常動作する。
- Wi-Fiやスマホがなくても、サンニー単独で世界は成長し、本体を操作できる。ただし正確な経過時間の復元とタイマー起床には同期済み時計の扱いを確定する必要がある。

## 3. 本体240×240の操作仕様

### 通常の6世界

表示順: `自然 → 街 → 共生 → 魔法 → 森 → 水槽 → 自然`（循環）。

| 操作 | 本体での動作 | 備考 |
|---|---|---|
| 左／右スワイプ | 6世界を切り替え | タッチ誤判定を避けるしきい値は実機調整 |
| 画面タップ | 現在の世界へ干渉 | `engine.tap(world_id)` を再利用 |
| 長押し | 小さなクイックメニュー | 当面「戻る・時刻・接続情報・電池情報」。画面中央を極力塞がない |
| 水槽で上下スワイプ | 川・海・深海を選択 | 未解放エリアは切り替えず短い鍵演出 |
| 水槽以外の上下スワイプ | 何もしない | 予期せぬ操作をなくす |
| 電源スリープ中のタッチ | **起床しないことを初期仕様とする** | 外部ウェイク回路／RTC GPIOが使えるか未検証 |

- 画面外周の6点でモード位置を示す。イベント・電池警告は小さく短時間で重ねる。
- フレームレート・メモリ使用量・タッチジェスチャーの再現性は実機で測る。滑らかさと消費電力は測定後に調整する。
- 起床直後は最後に本体で選択したモードを復元。スマホ側で閲覧していたモードには影響されない。
- GC9A01A/CST816Sを扱うライブラリは公式の基板配線に合わせて選定する。ドライバができるまで「本体表示できる」と宣言しない。

### 表示世界と水槽エリアの状態

ESP32で `display_world`（`nature/city/hybrid/fantasy/forest/aquarium`）と `display_water_area`（`river/ocean/deepsea`）を保持する。水域は`aquarium`表示中のみ使用する。

- 水域解放情報は `world_model.py` が所有。表示設定だけで海・深海を解放しない。
- 新しく解放された海・深海はアプリに通知するが、勝手に本体表示エリアを変更しない。
- 不正なモードID・未解放の水域が指定されたら、状態を変更せずエラーを返す。
- 本体表示状態は世界データと分けて保存し、シミュレーションセーブとの互換性を守る。

## 4. スマホアプリの画面設計

既存の下部タブ3つは維持する。

### 「観察」

- 接続状況、端末の現在表示モード、電池の概況を上部に表示（電池は取得可能になってから）。
- スマホ画面は6世界を自由に観察・拡大。水槽は解放済みの川・海・深海を選択。
- 「**サンニーに表示**」を押すと、明示的に本体画面だけを切り替える。
- 未接続ならデモ表示と実機表示を混同せず、「未接続・デモ」などと明記。
- スリープ中は接続できないことを明記し、アプリは最後に取得できた起床予定時刻を**キャッシュ情報**として表示（最新状態とは断言しない）。

### 「更新」

- 現行の `/api/upload`（画像・データ・`world_model.py`・`index.html`）を維持。
- 更新対象・プレビュー・送信確認・失敗時のメッセージを明確にする。
- **`main.py`・`settings.py`・MicroPython自体は現在OTA未対応。** ブートストラップと復旧はUSB必須。
- バッテリー電圧が危険／本体がスリープ直前なら更新を拒否する設計（実装時に電圧測定と連動）。途中で眠らないよう、更新処理中はスリープ遷移を保留する。

### 「設定」

- Wi-Fi接続、接続テスト、認証キー保存（既存）。
- 電源・生活時間（別設計書）：起床／就寝・曜日・時刻同期・画面の明るさ・電池情報。
- 本体表示モード・音反応ON/OFF・必要に応じて将来のマイク感度設定。
- 再起動は確認を取る。スリープ操作は復帰予定と「夜間はスマホから起こせない」ことを表示。

## 5. 通信とAPI（設計案）

| HTTP | API | 用途 | 現状 |
|---|---|---|---|
| GET | `/api/info` | 名前、バージョン、更新可否 | v0.3実装済 |
| GET | `/api/state?clock=...` | 6世界の状態 | v0.3実装済 |
| POST | `/api/touch?world=...` | 世界へのタップ | v0.3実装済 |
| POST | `/api/upload` | 認証付きデータ更新 | v0.3実装済 |
| POST | `/api/restart` | 認証付き再起動 | v0.3実装済 |
| GET | `/api/display` | 本体が表示しているモード／水域 | 未実装 |
| POST | `/api/display` | 本体のモード／水域の変更 | 未実装。管理キー認証 |
| GET/POST | `/api/power...` | 時間設定、スリープ、電池、時刻同期 | 未実装。別設計書 |

- AP方式は端末自身が `SANNY-ESP32` を配信、通常接続先 `192.168.4.1`。
- 開発・実証時は職場LANに勝手に参加させない。個人Wi-Fi設定の秘密値をリポジトリへコミットしない。
- スリープ中はHTTPに応答できない。アプリで「接続拒否＝故障」と扱わない。
- 更新APIと設定APIの呼出しは競合しないよう、電源遷移・更新中フラグを共通管理する。

## 6. 演出の統一ルール

- 6世界ごとの「おやすみ→朝」演出は [生活サイクル設計書](LIFE_CYCLE_POWER_ENCLOSURE.md#4-丸形lcdの共通ui) を参照。
- 本体の円形画面は、最優先が景色。UIは外周リングや短い通知に寄せる。
- 充電が検出できた場合は、世界ごとの蛍・光・泡・魔力で表現。ただし**実際の充電状態を誤って表示しない**ことが条件。
- 音に反応する演出は現在の `observe_sound(level)` の挙動を起点にする。外付け6ピンマイクの結線が決まるまでは疑似入力のみ。会話内容を録音・保存しない。
- 休日・スリープの時間経過で大きな変化があった場合は、朝の数秒間に「昨夜、森で新しい木が育ちました」など1件だけまとめて表示する。世界進行の実イベントから生成し、架空の出来事を表示しない。

## 7. 接続テストと受け入れ条件

1. 本体を自然モードに固定したまま、スマホで街→魔法→森へ切り替えても本体表示は変わらない。
2. スマホの「サンニーに表示」を押したときだけ本体の表示モードが変わり、再起動後も保持される。
3. 本体タッチとスマホの変更が同時に来た場合、順序を保存して不正な状態にしない。
4. 水槽で未解放の深海を選択できず、解放後に利用可能になる。
5. アプリから退勤時刻を変更したらESP32側で永続化され、スマホが離れても予定時刻に休眠する。
6. 夜の間はスマホがアクセスできないが、翌朝は自動起床してアクセスポイントが復帰する。
7. 休日を挟んでも世界の成長時間が正しく積み上がる。48時間の復元制限との衝突をテストする。
8. 電池不足や更新失敗が起きても物理的にBOOT/RESETにアクセスでき、USBで復旧できる。
9. すべての機能についてCPythonやAndroidのソース検証と、**ESP32・スマホ実機検証を明確に区別する**。

## 8. 優先順位

- **第一段階:** 画面・タッチドライバーの成立性確認、共通状態の定義、アプリの表示と独立した本体表示モードAPI。
- **第二段階:** 生活時間の設定保存、時計同期、夜間ディープスリープと翌朝タイマー起床、世界の時間補完。
- **第三段階:** 電池電圧の校正、充電検出と演出、消費電力測定とバッテリーサイズ選定。
- **第四段階:** 6ピンマイク実装（型番確認後）、筐体試作、BOOT/RESET救済、長時間の実機テスト。

## 9. 追加決定: ジャイロと加速度で世界に触れる

ユーザー確定仕様（2026-11-18）: **基板内蔵の6軸センサーを利用する**。Waveshare公式ではQMI8658（3軸加速度＋3軸ジャイロ）の搭載を確認できる。**追加のジャイロ基板は不要**。6ピン外付けマイク用のピンを流用しない。

### 操作の優先順位（初期デザイン）

| 動作 | 通常動作 | 理由 |
|---|---|---|
| サンニーをゆっくり傾ける | 景色に小さな視差・重力演出 | デスクの世界が「本当に中にある」感覚 |
| サンニーを水平に戻す | 徐々に元の位置へ | 操作中の画面酔い・急な反転を防ぐ |
| 軽く振る | アプリで有効にした場合のみ小さなイベント | デスクへの衝撃で誤発動しないよう初期OFF |
| ケースを180度回す | 希望に応じて画面方向を補正 | 自動回転は設定でON/OFF |
| ディープスリープ中に動かす | 初版では**起床しない** | IMU割込みによる起床可否は実機未検証 |

**ジャイロで勝手にモード切替しない**。モード切替はタッチ・スマホ指示のままにする。感度とフレームレートは本体とケースの重量で実測後に決める。

### 6世界の物理反応（演出デザイン案）

| 世界 | 傾きへの反応 | 軽い振動イベント（設定ON時のみ） |
|---|---|---|
| 自然 | 雲や葉が少し流れる | 木の葉が舞う |
| 街 | 遠景と建物の視差 | 窓に明かりが一瞬灯る |
| 共生 | 木々と街の視差が異なる | 小さな風が抜ける |
| 魔法 | 星や粒子が重力に沿って漂う | 魔力のきらめきが増える |
| 森 | 葉やホタルが傾く方向へ移動 | 木の実が落ちる |
| 水槽 | 泡や水草の向きが変わる | 水面に波紋が広がる |

魚・住人・植物などの**成長データや解放条件には、誤検出で影響させない**。まず視覚効果だけを実装し、十分に検証した後で任意イベントを増やす。

### ソフト設計と検証

1. `motion_adapter`（仮名）がQMI8658の加速度（静的な重力方向）と角速度（回転）を読む。**傾斜角度をジャイロ値だけで推定しない**。
2. ノイズ軽減フィルタ、デッドゾーン、最大移動量、振り判定のクールダウン、長時間静止での省電力を設ける。実数値は未確定。
3. `render_frame(world, motion)` のように描画用の動きと世界データを分離し、誤動作で世界の保存データが変わらないようにする。
4. アプリの設定に「動きに反応」「感度」「振ってイベント」「自動回転」を追加する構想。すべて本体側に保存。
5. I2Cバスはタッチ（CST816S）との共有を考慮し、競合・応答遅延を実機で試験する。基板の公式配線に従う。
6. **夜間・土日祝日のスリープを最優先**し、動きで予期せずWi-Fiや画面が起きないことを確認する。
