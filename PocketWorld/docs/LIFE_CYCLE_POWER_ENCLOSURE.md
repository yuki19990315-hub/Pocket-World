# サンニー 生活サイクル・電池・外装の設計記録

**v0.6実装メモ（以下には初期設計の未更新部分を含む）:** 勤務時間外のバックライト消灯と翌勤務時間の点灯、Android輝度10〜100%の設定、低電圧警告、最大7日分の離席時間復元を実装した。Wi-FiやCPUも止めるディープスリープは実機電池・タイマー起床の検証前につき初期OFF。充電中の自動判定、バッテリー容量測定、外装は未実装。電源の現行動作は[README](../README.md)を優先する。

**現行の1日演出:** Androidで設定した起床〜就寝時間を、昼・夕暮れ・夜までの1日に圧縮。初期例8:30日の出／15:00夕焼け／16:00街灯・家の点灯／17:30全消灯・画面OFF。30分の朝、夕方の1時間、夜の1時間半は活動時間に比例して変化する。土日祝日は消灯。ディープスリープには専用安全ロック `ENABLE_DEEP_SLEEP=True` と実機復帰確認が必要で、初期値はFalse。夜の点灯は描画上の演出であり、基板に実際のLEDや街灯が増設されるわけではない。

状態: **設計確定候補 / ソフト実装前 / ESP32実機未検証**  
更新: 2026-11-18（日本時間）  
対象: Waveshare **ESP32-S3-Touch-LCD-1.28**、Pocket World（6世界）、Android「サンニー Companion」

## 1. 目指す体験

「見ていない間も生きている、小さな世界」。

- 職場のデスクでは、**勤務時間中は丸形ディスプレイを常時点灯**し、現在の世界を表示する。
- 退勤時間には世界ごとの「おやすみ」演出を出す。ゲーム状態を保存し、バックライトと表示を消し、ディープスリープへ入る。
- 翌朝は**スマホが近くになくてもタイマーで自動起床**し、朝の演出とともに表示を戻す。
- 就寝中の時間も世界の成長に反映する。強制停止・電池切れ・誤った時刻には安全側で振る舞う。
- アプリで「起床時刻・就寝時刻・曜日・タイムゾーン・手動休眠」を設定する。電池の容量・持続時間は実機測定後に決める。

**未決定:** 実際の勤務時間、個別の臨時休業日、電池の型番・容量、6ピンマイクの型番、外装寸法。アプリ上の時刻例は、ユーザーの勤務時間の確定情報ではない。

## 2. 電源状態のモデル

| 状態 | 画面 | Wi-Fi | 世界の扱い | 抜け方 |
|---|---|---|---|---|
| ACTIVE | 常時表示（輝度は設定可能） | 通信可能 | 1分ごとに進行 | 就寝時刻／手動休眠／危険電圧 |
| GOOD_NIGHT | 演出表示（例: 5〜15秒） | 受付を終了 | 書き込みと正常終了 | DEEP_SLEEPへ |
| DEEP_SLEEP | OFF | **通信不可** | 起床後に経過時間を補完 | RTCタイマー等で復帰 |
| BACKGROUND_WAKE | OFF | 原則OFF | 休日などの長い眠りを小分けに補完 | 再休眠 or ACTIVE |
| MORNING | 朝の演出後に表示 | 再起動／接続再開 | 保存データ復元 | ACTIVE |
| MAINTENANCE | 必要に応じて表示 | 復旧用 | 更新や故障診断 | 明示操作 |

充電中（CHARGING）と残量警告（LOW_BATTERY）は、これらの状態に重なる**表示・安全フラグ**として扱う。充電中だから世界がリセットされたり、誤って早朝起床したりしない。

### 必須の状態遷移ルール

1. 端末は初回セットアップ後、**自分の内部時刻を使って**勤務時間帯を判断する。設定用のスマホ接続が常時必要であってはならない。
2. **時刻が未同期・無効、または復帰時刻を安全に計算できない場合は自動ディープスリープしない。** アプリに「時刻の同期が必要」と表示する。
3. スリープに入る前に、6世界とタイムアンカー・次回起床予定を安全に保存する。中断で壊れないよう一時ファイル＋差し替えを検証する。
4. 深い眠りではWi-Fiが無効なので、**スマホから即時起床する機能は初期仕様に含めない。** 手動スリープを押す際は確認ダイアログと次回自動起床時刻を表示する。
5. 休日に48時間以上眠る場合、現行の世界復元上限（1回48時間）を超えないよう、**最大12時間ごとのバックグラウンド起床**で経過時間を積み上げ、画面を点けずに再休眠する案とする。ソフト実装と電力実測が必要。
6. 電池が危険な状態では保存を試みる。ただし書き込み可能な残電力と実機の遮断動作を確認するまで、自動安全停止のしきい値を固定しない。

### 時計・起床の設計

- アプリがサンニーに現在のUTC epochとタイムゾーン（初期値は `Asia/Tokyo`）を送る。
- ESP32は同期後に内部時計を管理し、設定曜日・起床／就寝時刻から次の遷移時刻を算出する。
- 夜間はRTCのタイマー起床を使う。ディープスリープ復帰後に、時刻と復帰理由を検証する。
- 停電・電池切れからの復帰、時刻のドリフト、ユーザーが時刻を変更した場合の扱いを別途検証する。
- 現行の `world_model.py` の最大48時間の復元制限との整合性は必須。**土日休眠を普通に行うだけで世界の成長が途切れない設計**とする。

## 3. スマホアプリの「電源・生活時間」

既存の下部タブ `観察 / 更新 / 設定` は維持。設定画面に独立した `サンニーの生活時間` カードを追加する。

### 入力

| 項目 | 入力・規則 |
|---|---|
| 自動起床・就寝 | 有効 / 無効（初回は未設定。ユーザーが保存して有効化） |
| 起床時刻 | 時刻ピッカー、24時間表記 |
| 就寝時刻 | 時刻ピッカー、24時間表記 |
| 稼働曜日 | 月〜日のチェック（**決定: 月〜金のうち、日本の祝日・休日を除いて稼働**。土日は休眠） |
| タイムゾーン | 初期 `Asia/Tokyo`。初版では固定も可、表示で明示 |
| 画面輝度 | 実機LCDドライバー実装後にスライダー |
| 手動スリープ | 確認後、次の稼働開始まで眠る（復帰時刻を必ず表示） |
| 今すぐ再起動 | 既存の認証付き再起動APIを使用 |
| バッテリー | 最初は電圧と段階表示。％、充電状態は検証後に有効化 |

- 「保存」は**ESP32側の設定が書き換わって初めて成功**と表示する。スマホだけの保存で成功としない。
- 通信が切れた場合は「未反映」と表示し、再接続して再送する。
- アプリで別の世界を観察しても、サンニー本体の表示世界は勝手に変えない（別途「サンニーに表示」操作）。
- スリープ中は「オフライン／予定起床時刻」を表示する。スマホからの起床ボタンは出さない。

### API契約（設計案。現在は未実装）

| HTTP | パス | 目的 | 認証 |
|---|---|---|---|
| GET | `/api/power` | 現在の状態・設定・電池電圧・時計同期状態を取得 | ローカルAP接続 |
| POST | `/api/power/schedule` | 生活時間と稼働曜日の変更 | `X-Admin-Key` |
| POST | `/api/time` | アプリ端末時刻を同期 | `X-Admin-Key` |
| POST | `/api/power/sleep` | 次の起床予定を提示したうえで手動休眠 | `X-Admin-Key` |

設計例（JSON）: `{"enabled":true,"wake":"08:00","sleep":"18:00","active_days":[1,2,3,4,5],"timezone":"Asia/Tokyo"}`。曜日番号は月曜=1〜日曜=7。実際のスキーマは実装テスト時に確定する。

セキュリティ: SANNY-ESP32のローカルAPでのみ通信し、変更操作は更新用管理キーで認証する。秘密のWi-Fiパスワードや管理キーをGitHubに保存しない。

## 4. 丸形LCDの共通UI

240×240のGC9A01Aを前提に、中央180×180程度を世界の主要な景色に使い、外周の一部に通知を重ねる。**画面物理実装は未着手。**

- 昼: 6世界それぞれが通常の生活を送る。日常的に電池マークを出しっぱなしにしない。
- 夜: 日が沈む → 住人が帰宅 → 窓の光が消える → おやすみ → 画面OFF。途中で世界の現在状態を保存する。
- 朝: 暗い世界に光が戻る → 朝の活動開始。設定時刻を過ぎた復帰でも無理に長い演出を再生しない。
- 低電池: 景色を隠さない小さな「生命の光が弱い」サイン。危険時は明確な文言（充電してね）も出す。
- 充電中: 各モードの演出に重ねる。森=ホタル、川/海/深海=泡と光、街=家の明かり、自然/共生=太陽の光、魔法=魔力、惑星イメージ=流星。**実際のモード名は既存6モードに合わせ、惑星は将来追加する案として扱う。**
- 充電完了: 判定信号を確認できた場合のみ実装する。電池電圧上昇だけで充電中・満充電を断定しない。
- 充電中でも就寝時間には画面OFFを優先。ただし「夜間充電中も何か表示したい」要望が出たら、誤認識を防ぐためUSB接続検出ハードウェアを先に検討する。

### 世界ごとの夜・朝の演出（デザイン案）

| 既存モード | 就寝前 | 翌朝 |
|---|---|---|
| 自然 | 太陽が沈み、動物が巣へ | 花と動物が動き出す |
| 街 | 住人が帰宅して各家の窓が消灯 | 窓が灯り、住人が出勤 |
| 共生 | 森は静まり街は帰宅 | 双方の活動が再開 |
| 魔法 | 星と魔力が夜空へ集まる | 小さな光が街に降る |
| 森 | 小動物が眠り、ホタルが最後に消える | 光が葉の間から差す |
| 水槽 | 泡がゆっくりになり、魚が静かに | 朝の水面から光が入る |

## 5. 電池・充電のハード設計

公式製品情報で**確認済み**:

- 3.7Vリチウム電池用のMX1.25 2ピンコネクターとETA6096充電回路を搭載。
- GPIO1は電池電圧測定用のADC入力として説明されている。
- USB-C端子、BOOT、RESETが存在する。
- 1.28インチ丸形タッチLCDはGC9A01A／CST816S。

**未確認／測定待ち**:

- GPIO1の生ADC値を正しく電池電圧に変換できるか。USB接続時の挙動、ボードの基板版差を要確認。
- 充電ICの「充電中」「満充電」信号をESP32で読めるか。公式資料の電圧ADCだけで充電ステータスを表示できるとは扱わない。
- 使用するリチウム電池の容量・厚さ・端子極性・保護回路、発熱、平均消費電流。
- 追加の充電ステータス検出回路が必要か。外付け6ピンマイクとのGPIO競合がないこと。
- 常時点灯＋Wi-Fi待受＋マイク使用時の稼働時間。電池容量はこの測定後に決める。

安全方針: 電池コネクターの**極性と電池の保護回路を実機・製品資料で照合**する。生セルをGPIOや5Vへ接続しない。電池をネジ・金属外装で押しつぶさない。充電中の温度上昇を確認する。

## 6. ケースとボタン

### 推奨構造

- 表: 丸形LCD全面。タッチ操作で6世界の切り替え（実機ドライバー実装待ち）。
- 側面/底面: **USB-Cに普段からアクセス可能な開口部**。充電ケーブルが挿し込める余裕を確保。
- 裏面: **取り外せる小さなメンテナンス蓋**。開けるとBOOT/RESETに物理アクセスできる構造を最優先。
- 内部: 電池用ホルダーと絶縁材。端子の向きを間違えない配置とし、基板・バッテリー・配線を固定。
- 外付け6ピンマイク: 型番と配線を確認するまではスペースだけ予約し、GPIOを決め打ちしない。

**理由:** 現行アプリの再起動APIはソフトが正常稼働しているときだけ使える。更新失敗時はUSB・BOOT・RESETによる救済が必要。ケースで完全に封印しない。

ケース候補: スナップ式裏蓋、隠し小ネジ式裏蓋。ピンホール式は基板上のボタン位置・操作感を実測してから。マグネットは電子部品/バッテリーへの干渉と外れやすさを考えて後回し。

## 7. 予定実装順と受け入れテスト

### Phase A — 時間設定と安全な制御モデル（PCで検証可能）

1. 純粋なスケジューラ: 曜日・時刻から稼働／休眠・次回起床を算出する。
2. ESP32のスケジュール保存と認証付きAPI。時計未同期時はスリープ禁止。
3. Android設定UI、保存確認、オフライン時の未反映表示。
4. テスト: 曜日切替、金曜夜〜月曜朝、日付跨ぎ、無効時刻、時刻未同期、設定変更、二重保存。

### Phase B — 丸形実機とディープスリープ（実機必須）

1. GC9A01A描画とCST816Sタッチを先に動かす。バックライトOFFと再起床表示を検証。
2. 夜の保存→タイマースリープ→翌朝の復帰→世界進行復元を検証。
3. 土日のバックグラウンド起床と世界時間補完を検証。RTC精度と誤復帰を測定。
4. アプリが夜にWi-Fi接続できないことを確認し、UIに起床予定を出す。
5. 再起動ループ・不正な時計・電源断時には安全に復旧できる動作を作る。

### Phase C — 電池と充電演出（実機必須）

1. GPIO1電圧値をUSB接続時／電池運用時に校正。
2. 残量警告は段階式・ヒステリシス付き。しきい値は保護回路と測定に合わせる。
3. 充電状態の取得方式（使える信号／追加回路）を特定してから演出を有効化。
4. 平均電流、輝度、AP待機電力、マイク接続時、充電温度を測り電池容量を選ぶ。

### Phase D — 外装と故障復旧（実機必須）

1. 基板・バッテリー・マイク寸法の現物測定、USB-Cの挿抜クリアランス。
2. BOOT/RESETにアクセスできる蓋の試作。
3. 故障想定のUSB再書き込みテスト。組み立て後も復旧できることを確認。

## 8. 現行v0.3との差分と注意

- 現行リポジトリは6世界のシミュレーションとスマホ表示・無線データ更新までで、**丸形液晶制御・バッテリー状態表示・スケジュールAPI・ディープスリープ・充電検出・ケース設計は未実装**。
- 新しい `main.py` の配布は現行OTAの対象外。導入時はUSBでファームウェアファイル更新が必要。
- 電源を落とす前の世界保存と、復帰後の経過時間補完は動作条件としてテストしなければならない。
- Android APKのビルド成功は実機でのESP32動作成功を意味しない。
- この設計書は**仕様と実装順の確定**であり、端末での動作や試験完了を宣言しない。

## 9. 追加決定: 土・日・日本の祝日は画面OFF

ユーザー確定仕様（2026-11-18）: **土曜・日曜および日本の「国民の祝日・休日」は終日休眠**。月〜金のみを勤務日候補とし、祝日・振替休日・国民の休日は除外する。

- 金曜の退勤後は、次の稼働対象日（通常は月曜、祝日なら火曜以降）の起床時刻まで画面OFF。
- 祝日が平日なら「おはよう」演出を出さず、画面OFFを継続する。長い休眠中のバックグラウンド起床は画面に何も出さない。
- アプリには「祝日を休眠日にする」を初期ONで設ける。将来「会社の休業日」「有給休暇」の手動追加も可能にするが、会社独自の休日は**国民の祝日とは別**。
- 稼働時刻は今のところ未指定。時刻を勝手に確定しない。
- 祝日の公式データは、**内閣府が公開した2026・2027年の祝日・振替休日等**を採用する（[内閣府公式一覧](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)）。
- 同じ公式一覧では、**2028年の祝日は2027年2月に公表予定**と説明されている。2028年以降の日付を推測で作らない。
- 初期の配布用データは `firmware/assets/jp_holidays.json` に設計資料として追加。**現行のv0.3ファームウェアはこれをまだ読み取らない**。
- アプリを通じて年次データを送信する運用を設計する。古いデータのままでは正しい祝日判定ができないため、対象年が範囲外ならアプリに「祝日データ更新が必要」と明示する。
- 日付判定は **Asia/Tokyo の暦日**に基づく。UTCからの変換を内部で一貫させ、真夜中の境界をテストする。
- 安全な起床計算ができない／対応年が未知のときの扱いは、勝手に曜日だけで「祝日はない」と確定せず、**エラー表示＋明示的な更新案内**にする。実機で復帰できない状態を防ぐため、未確定年でのディープスリープ移行は保留する。

テスト追加予定: 2026-05-06（振替休日）、2026-09-22（国民の休日）、2027-03-22（振替休日）、2027年の年末、2028年（データ未公表）、祝日にまたがる金曜退勤、月曜祝日の火曜朝起床。
