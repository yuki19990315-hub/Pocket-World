# Pocket World v0.9 — 一匹のクラゲと7つの世界

## 一匹のクラゲ

7つ目の世界「一匹のクラゲ / Moon Jelly」を追加しました。ユーザーが選んだ写実的な生成画像を元に、暗い青の水槽にクラゲが1匹だけ漂います。画像の濃淡を残して傘の収縮・口腕のゆれ・静かな移動を本体とスマホで描画します。傾きにも静かに反応します。魚や来訪者は増えず、何日育てても1匹のままです。

本体の左右スワイプでは、水の世界の次に表示されます。スマホは観察画面を再読込し「クラゲ」を選びます。勤務時間による消灯・既存の6世界・セーブを引き継ぎます。初回USB更新には `jelly_tank.py`、`round_screen.py`、`index.html` と `/assets/jellyfish-tank.dat`・`/assets/jellyfish-tank.png` も含めてください。背景は `python PocketWorld/tools/build_jelly_tank.py` で再生成後、従来のJSビルダーでAndroidのパックにも同梱できます。

## 来訪者と来訪図鑑

図鑑が空の世界では最初の来訪が稼働約1分以内に起こり、その後は世界ごとに約3分おきに訪れ、32秒ほど滞在します。鳥・旅人・妖精・森の動物・水の生き物など24種類を用意しました。ときどき珍しい来訪が起こり、10回目ごとの来訪も珍しい種類になります。川・海・深海の生き物は、それぞれ解放済みの水域に現れます。

画面に出していない世界でも来訪が進みます。出会いの種類・回数は通常のセーブに残り、スマホの「来訪図鑑」と「世界の発見ノート」で振り返れます。旧セーブは進行を引き継いで図鑑を追加します。来訪だけで建物や住民の数は増えません。

本体はRAM上の背景から動いた部分を復元し、来訪者や周囲の小さな動きを約0.25秒ごとに更新します。初回USB更新では、従来のファイルとともに新しい `scene_events.py` も本体ルートへ配置してください。

Waveshare **ESP32-S3-Touch-LCD-1.28**（愛称 **サンニー**）向けの初期実装です。自然／街／共生／魔法／森／水槽の6世界を1台のESP32で保持し、スマホのブラウザまたは専用Androidアプリから観察できます。

**INMP441マイク拡張:** 画像でモジュールの種類・6端子表記が確認できたので、`firmware/inmp441.py` にI2S音量取得を追加しました。接続前なので `settings.ENABLE_MICROPHONE = False` が初期値です。候補の配線・安全条件・3種類の反応は[マイク接続ガイド](docs/MIC_INMP441_WIRING.md)を確認してください。スマホには音量の数値だけ送られ、音声録音は行いません。

> **現在の実装範囲:** 6世界の進行・保存、Wi-Fi、Androidアプリ、完成イラスト16場面のスマホ表示とGC9A01A丸形LCD表示コード、CST816Sタッチ、QMI8658傾き、INMP441音量の連携コード、電池電圧警告、認証付き素材更新。**PCテストは通過しましたが、COM7でのLCD表示やAndroid実機通信・バッテリー持続時間は未検証**です。安全のため深いスリープと外付けマイクは初期OFFです。

## NEW: 勤務時間を「サンニーの1日」にする

スマホアプリの「サンニーの生活時間」で起床・就寝時刻を設定すると、活動時間を**日の出→昼→夕焼け→夜→消灯**の1日に見立てます。初期入力例は8:30〜17:15で、以下の時刻に切り替わります。

| 時刻 | 世界の演出 |
| --- | --- |
| 8:30 | 日の出。少し暖かい朝の景色 |
| 9:00 | 通常の昼の色へ |
| 15:00 | 夕焼けが始まる |
| 16:00 | 青く暗い夜。街の家の窓と、新しい建物数に応じた街灯が点灯 |
| 17:15 | 家・街灯を消し、バックライトOFF。実機検証後のオプトイン時はタイマー付きディープスリープへ |

別の起床・就寝時刻に変更した場合も活動時間の比率（朝2/35・夕方26/35・夜30/35）で自動的に時刻を組み直します。土日と登録済み日本の祝日は休みです。スマホの観察画面には現在の空と各切替時刻、朝・昼・夕・夜のプレビューボタンを追加しました。色調と街灯はサンニー側のRGB565表示にも実装しています。

**重要:** `settings.ENABLE_DEEP_SLEEP=False` の初期状態は維持します。この場合、17:15には灯りと画面が消えてもCPU・Wi-Fiは動き続けます。実機COM7でのタイマー自動復帰、USB復旧、バッテリー電流の確認後に `True` へ変更すると、既存の `machine.deepsleep(ms)` によりWi-Fiも止まり、次の出勤朝に自動復帰します。スリープ中はスマホから接続できません。深いスリープはユーザーの実機ではまだ未検証です。

## v0.6: 机に置いて育て続けるための機能

- **本体の小さなアニメーション**：2枚の成長背景を保ち、約1.4秒ごとに水槽の泡や森の光の点を4個だけ移動。元の背景を4×4ピクセルずつ復元するので、画面全体を毎フレーム送り直さない仕組みです。実際の描画速度はCOM7で確認します。
- **街の住民は本物の1×3ピクセル**：誕生時は**家1軒・住民2人**。LCDの240×240ピクセル座標で、住民を頭1ピクセル・胴1ピクセル・足1ピクセルとして小刻みに歩かせます。前の3ピクセルは背景画像から復元し、残像を残しません。共生・魔法の住民も同じ1×3サイズで描画。描画人数は最大18人ですが、保存上の住民は最大40人です。
- **建物の数に応じて景色も成長**：街の初期背景は家が1軒のイラスト。3時間後に2軒目、その後も30日目まで新築イベントがあり、保存される建物数に合わせて成熟した街並みが段階的に現れます。スマホ・独立プレビューも同じ成長段階を使います。描画の変化は**2枚の完成イラストの段階的合成**であり、各建物を個別に1棟ずつ追加描画する方式ではありません。
- **6軸センサーの画面演出**：サンニー本体を傾けると光・泡の移動位置が少しずれ、設定で振動演出ONならキラキラが数フレーム明るくなります。世界の進行データ自体は変えません。
- **タッチ操作**：タップは世界に干渉、左右スワイプは6世界切替、水槽の上下スワイプは解放済みの川・海・深海を切替、長押しは電池電圧に応じた4段階ゲージ。タッチICの公式ジェスチャーレジスタと座標から判定します。方向と長押し時間は実機調整が必要です。
- **退勤後の画面OFF**：同期済み時計と仕事時間に従い、夜間・土日祝日のLCDバックライトを消灯。翌勤務時間には復帰します。**Wi-FiとCPUは動作し続けるため、真のディープスリープと同等の節電ではありません。** 深いスリープは従来どおり`ENABLE_DEEP_SLEEP=False`の安全ロックです。
- **明るさ設定**：Androidから10〜100%の輝度を読み書き。値は`display.json`に保存して再起動後も利用します。10%未満は誤って画面を見失わないよう拒否します。
- **成長を長期化**：街の建築、森の植物、水中の生き物が最初の数時間で増え切らず、30日目にも新しい変化が起こります。世界の発見記録は各モード最新24件まで保存・スマホで表示。以前の保存データは読み込み可能ですが、すでに増えた建物は減らしません。
- **長い休暇**：時計を使った不在時間の復元上限を48時間から7日へ拡大し、3連休や長めの週末で進行が失われにくくしました。
- **充電表示への準備**：将来、実際の充電信号を検出できたときだけ緑色の充電マークを出す処理を追加。**現状の基板だけでは充電中を自動検知できないため通常は表示しません。**

## v0.5: 完成した世界を本体とスマホで共有

- 街・自然・共生・魔法・森・水槽（川／海／深海）の**8景色×誕生時／成熟時＝16枚**の完成イラストを同梱。30日かけて背景を変化させます。スマホには小魚・泡・光・雨の動きを重ねます。
- 丸形画面は`firmware/round_screen.py`でRGB565を1行ずつSPI描画。背景は1分ごと、タッチやスマホからの世界変更時にも更新します。v0.6で軽量な点・泡の動きを追加しました。
- スマホは同じイラストを拡大し、**「この世界をサンニーに表示」**で本体の表示モードも変更できます。水槽の川・海・深海もスマホで解放済みのエリアを選んでから、本体にその景色を表示できます。
- Android「完成ワールドパックを送信」で、PNG16枚・RGB565データ16枚・更新済み観察ページ1枚の**33ファイル**を順に転送。初回の`main.py`や表示ドライバ導入はUSB経由です。
- GPIO1のADCで低電圧警告を出します。残量％や充電中の検知は未対応。充電ICの状態取得ピンは公式資料で確認できず、実際に検知できるまでは充電中マークを表示しません。

### 初回USB導入

`firmware`フォルダの`.py`10ファイル（`main.py`、`round_screen.py`など）を本体ルートへ、`www/index.html`を`/index.html`へ、`firmware/assets`の祝日JSONとRGB565 `.dat`16枚および`design/assets`のPNG16枚を本体`/assets/`へ配置します。Wi-Fiパスワードと管理キーを`settings.py`で設定してください。

`node PocketWorld/tools/build_display_assets.js` をリポジトリ直下で実行するとRGB565データとAndroid同梱の33ファイルを再生成します。ビルド時にNode.jsと`sharp`が必要です。

## v0.4: 土日祝日の休眠予定と6軸ジャイロの試作

- `firmware/work_schedule.py`: UTC epochを日本時間へ変換し、平日の起床〜就寝設定と日本の祝日・振替休日を照合。土日祝日は休眠、次の勤務朝に起床する時刻を算出する。現行の初期入力例は**08:30/17:15**（編集可能）。
- `firmware/power_runtime.py`: 設定ファイル `power.json` と認証付きAPI `GET /api/power`、`POST /api/power/schedule`、`POST /api/time` を追加。時計未同期・公式休日データ未収録年なら休眠しない。
- `firmware/qmi8658.py`、`motion_effects.py`: 基板内蔵QMI8658をI2Cから読み、傾き値とオプションの振動イベントに変換するコード。**QMI8658の読み取り・感度・画面への効果は実機未検証。** 振動イベント初期OFF。
- スマホのWeb画面は傾きに応じた軽い視差と振動時のキラキラを表示する。アプリ設定には時刻同期、起床／就寝時刻、振動イベントのON/OFFを追加。本体に保存できたときのみ成功と表示。
- **安全制限:** 丸形LCD表示のコードは追加したものの、正常起床・ボタン復旧・電池容量を実測できていない。`settings.ENABLE_DEEP_SLEEP = False`（初期値）のまま出荷し、**設定を保存しても自動ディープスリープは実行しない**。実機で安全に復帰できると確認した後に解放する。
- 公式休日データは `firmware/assets/jp_holidays.json` に2026/2027年分のみ含む。2028年以降は内閣府の公表後に更新する。休日が未収録の年に誤って休眠しない。

**v0.4を新規にESP32へ入れる際は**、通常の5ファイルに加えて `work_schedule.py`、`power_runtime.py`、`qmi8658.py`、`motion_effects.py`、`inmp441.py` と、`/assets/jp_holidays.json` も転送する。既存v0.3端末に対して、`main.py` と新しいモジュールの追加は現在の無線更新APIでできないので**USBで更新**する。写真やパスワードのバックアップも確認する。

## 🌲 森と 🐠 水の世界

- **森:** 小さな森の断面図を眺めるモード。木、落ち葉、土の中の根、キノコ、ホタル、小動物を描画し、植物と生き物が自動で育ちます。森の季節は3日ごとに切り替わる初期設定です。
- **水槽:** 川（淡水）・海（サンゴ礁）・深海の3つの独立した生態系。初期状態は川だけで、**累計進行1日（1440分）で海、3日（4320分）で深海**を解放します。海水魚は川の水槽へ移動せず、それぞれ自動で増えます。餌やりは必須ではありません。
- **スマホ表示:** 水槽には3つの切替ボタンがあり、それぞれ別の完成イラストを描画。未解放エリアは鍵マークで選択不可。デモでは3エリアを自由に見られます。
- **セーブ互換:** 従来の4世界の保存データは残したまま、新しい森と水槽を初期状態から追加します。

すでにv0.2のサンニーを動かしている場合は、専用Androidアプリの「更新」から、新しい `world_model.py` と `index.html` を順にアップロードして再起動すると新モードのデータ管理とスマホ画面を更新できます。`main.py` 自体を更新する場合はUSB接続が必要です。実機での更新成功は未検証のため、可能なら先に保存ファイルのバックアップを取ってください。

※海・深海の自動解放はゲーム内の累計進行時間に基づきます。電源OFF中の経過復元にはスマホの時刻同期が必要で、v0.6の復元上限は1回7日間です。時計が未同期なら暦日どおりにならない場合があります。

## 🎤 音で変わる世界（マイク実機接続待ち）

ユーザーの画像から外付けモジュールがINMP441であることと6端子の表記を確認しました。**I2Sの読み取りコードは追加済みですが、実機基板の接続先・感度は未確認**のため、初期状態では読み取りを無効にしています。音量値に反応する世界のシミュレーション処理と、スマホ画面のマイク状態表示は接続後に利用できます。

| 世界 | 音への反応 |
| --- | --- |
| 🌿 自然 | 静かなら晴れ、中程度なら風、にぎやかなら雨 |
| 🏘️ 街 | 活気のある音が継続すると住民や建物が少しずつ増える |
| 🌾 共生 | 自然の天候変化と街の発展が両方起こる |
| ✨ 魔法 | 大きな音が魔力になり、複数回の蓄積で珍しい流れ星が現れる |
| 🌲 森 | 音量に応じて晴れ・風・雨が変化する |
| 🐠 水槽 | 音量の変化で波紋や泡のできごとが発生する（実際の音声入力は未接続） |

`firmware/world_model.py` の `engine.observe_sound(level)` に正規化した音量 **0〜100** を約60秒に1回渡す方式です。暫定しきい値は静か `0〜24`、活動中 `25〜69`、にぎやか `70〜100`。**実際のマイクの感度を測って決めた数値ではなく、接続後に調整する初期設定**です。

生音声・会話・録音ファイルは取得・保存しません。各世界の進行カウンターだけを保存し、マイク状態は再起動で未接続に戻します。`ENABLE_MICROPHONE=False` が初期値なので、**配線と実機動作を確認してから明示的にONにする必要があります**。ピン配置を推測して結線しないでください。

## まずスマホ表示を確認する（ESP32への書き込みなし）

`www/index.html` をPCやスマホのブラウザで開きます。ESP32に接続されていない場合はオレンジ色の **デモ表示** になり、架空の6つの世界を体験できます。これは実機の保存データとは独立しています。

## ESP32で実際の世界を動かす

1. すでにESP32に別のファームウェアやRadio Roamのデータがある場合は、**先にバックアップ**してください。MicroPythonを書き込むと既存データを消す場合があります。
2. Waveshare公式ドキュメントに沿って、対応するMicroPython環境をセットアップします。MicroPythonのバージョンによって周辺機器のドライバー構成が異なる場合があります。
3. `firmware/settings.py` の `AP_PASSWORD` を8文字以上の**自分だけのパスワード**へ変更し、`ADMIN_KEY` を長く推測されにくい秘密の文字列に変更します。初期値のままでは無線更新は無効です。職場のWi-Fiの利用が許可されていない場合は、`STA_SSID` を空欄にします。
4. Thonnyなどを使い、以下をESP32のファイルシステム直下に転送します。

   - `/main.py` ← `firmware/main.py`
   - `/world_model.py` ← `firmware/world_model.py`
   - `/settings.py` ← `firmware/settings.py`
   - `/safe_update.py` ← `firmware/safe_update.py`
   - `/index.html` ← `www/index.html`

5. ESP32を再起動します。スマホのWi-Fi一覧で `SANNY-ESP32` を選び、設定したパスワードで接続します。
6. スマホのブラウザで **http://192.168.4.1/** を開きます。
7. 画面右上が緑色の「ESP32に接続中」になれば、ESP32が保持する6世界を表示しています。

**注意:** この接続方式はESP32がWi-Fiを提供するため、スマホは接続中に同じWi-Fi経由のインターネットへは出られません。Androidが「インターネットなし」と表示したら、必要に応じて「このネットワークを使用」を選択してください。職場のネットワークに自動接続する仕組みではありません。

## 専用Androidアプリからサンニーを更新する

同梱の `SannyCompanionAndroid` プロジェクトをAndroid Studioでビルド・インストールします（詳しくは専用README）。

1. アプリの「設定」で `SANNY-ESP32` につなぎ、管理用キーを登録します。
2. 「観察」タブでPocket Worldの6世界を開きます。
3. 「更新」タブからファイルを選択し、アップロードします。
4. `world_model.py` を更新したときは「サンニーを再起動」を実行します。

無線更新の対象は `index.html`、`world_model.py`、`assets/` 以下の `.png` / `.jpg` / `.json` / `.dat` ファイル（1個128KiB以下）です。`main.py`、`settings.py`、MicroPythonファームウェア全体は上書きできません。v0.5では規定ファイル名の素材を差し替えた後、スマホ再読み込み／本体の次回再描画で反映する設計です（実機未検証）。Androidアプリは33ファイルの一括転送に対応します。

アップロード処理は受信完了後にファイルを差し替え、以前のファイルは同じ場所に `.bak` として保存します。壊れたプログラムによる起動失敗を完全に自動復旧する機能は未実装です。初回導入や復旧時はUSB接続が必要になることがあります。

## 仕組み

- ESP32が6世界の共通状態を管理し、表示中ではない世界も1分ごとに進みます。
- スマホは5秒ごとに `/api/state` を取得して画面を描き直します（ゲーム状態の決定はESP32側）。
- タップすると `/api/touch?world=...` に操作を送ります。
- 約5分ごとにESP32のFlashへ状態を保存し、停電・再起動後も再開します。ただし突然の電源断では、最後の保存以降の進行は失われることがあります。
- スマホと時刻同期した際、最大7日分まで離席中の進行を復元します。スマホ時刻が誤っていると進行も変わるため、正しい時刻で同期してください。
- スマホにつながない、かつ時刻同期できない場合は、ESP32の稼働時間の分だけ進みます。電源OFF中の正確な経過時間を完全に再現するには、RTCなどの追加が必要です。
