# Pocket World v0.4 — サンニー × 6世界テラリウム

Waveshare **ESP32-S3-Touch-LCD-1.28**（愛称 **サンニー**）向けの初期実装です。自然／街／共生／魔法／森／水槽の6世界を1台のESP32で保持し、スマホのブラウザまたは専用Androidアプリから観察できます。

**INMP441マイク拡張:** 画像でモジュールの種類・6端子表記が確認できたので、`firmware/inmp441.py` にI2S音量取得を追加しました。接続前なので `settings.ENABLE_MICROPHONE = False` が初期値です。候補の配線・安全条件・3種類の反応は[マイク接続ガイド](docs/MIC_INMP441_WIRING.md)を確認してください。スマホには音量の数値だけ送られ、音声録音は行いません。

> **現在の実装範囲:** 6世界の軽量シミュレーション、保存・再開、GC9A01A丸形LCDへの描画、CST816Sのタップ操作、ESP32 Wi-Fiアクセスポイント、スマホ表示と認証付き無線ファイル更新。

## v0.4: 土日祝日の休眠予定と6軸ジャイロの試作

- `firmware/work_schedule.py`: UTC epochを日本時間へ変換し、平日8:00〜18:00などの設定と日本の祝日・振替休日を照合。土日祝日は休眠、次の勤務朝に起床する時刻を算出する。起床／就寝時刻はアプリから変更できる。時間はユーザー未指定のため**08:00/18:00は編集可能な仮の値**。
- `firmware/power_runtime.py`: 設定ファイル `power.json` と認証付きAPI `GET /api/power`、`POST /api/power/schedule`、`POST /api/time` を追加。時計未同期・公式休日データ未収録年なら休眠しない。
- `firmware/qmi8658.py`、`motion_effects.py`: 基板内蔵QMI8658をI2Cから読み、傾き値とオプションの振動イベントに変換します。振動イベントは初期OFFです。
- スマホのWeb画面は傾きに応じた軽い視差と振動時のキラキラを表示する。アプリ設定には時刻同期、起床／就寝時刻、振動イベントのON/OFFを追加。本体に保存できたときのみ成功と表示。
- **電源制御:** 設定した勤務時間に合わせてバックライトを制御します。復帰・ボタン復旧の検証まで `settings.ENABLE_DEEP_SLEEP = False` を維持します。
- 公式休日データは `firmware/assets/jp_holidays.json` に2026/2027年分のみ含む。2028年以降は内閣府の公表後に更新する。休日が未収録の年に誤って休眠しない。

**v0.4を新規にESP32へ入れる際は**、通常の5ファイルに加えて `work_schedule.py`、`power_runtime.py`、`qmi8658.py`、`motion_effects.py`、`inmp441.py` と、`/assets/jp_holidays.json` も転送する。既存v0.3端末に対して、`main.py` と新しいモジュールの追加は現在の無線更新APIでできないので**USBで更新**する。写真やパスワードのバックアップも確認する。

## 次期設計：日中常時表示・夜間休眠

現行版は時刻同期後、勤務中は常時表示し、退勤後・土日祝日は消灯します。稼働したまま次の勤務時刻に再点灯します。将来の「おやすみ」演出、タイマー起床、電池運用の試験計画は[生活サイクル・電池・外装設計書](docs/LIFE_CYCLE_POWER_ENCLOSURE.md)を参照してください。

## 🌲 森と 🐠 水の世界

- **森:** 小さな森の断面図を眺めるモード。木、落ち葉、土の中の根、キノコ、ホタル、小動物を描画し、植物と生き物が自動で育ちます。森の季節は3日ごとに切り替わる初期設定です。
- **水槽:** 川（淡水）・海（サンゴ礁）・深海の3つの独立した生態系。初期状態は川だけで、**累計進行1日（1440分）で海、3日（4320分）で深海**を解放します。海水魚は川の水槽へ移動せず、それぞれ自動で増えます。餌やりは必須ではありません。
- **スマホ表示:** 水槽内には3つの切替ボタンを表示。未解放エリアは鍵マークで選択不可にします。ESP32に接続していないブラウザのデモ表示では、デザイン確認のため3エリアを自由に見られます。
- **セーブ互換:** 従来の4世界の保存データは残したまま、新しい森と水槽を初期状態から追加します。

すでにv0.2のサンニーを動かしている場合は、専用Androidアプリの「更新」から、新しい `world_model.py` と `index.html` を順にアップロードして再起動すると新モードのデータ管理とスマホ画面を更新できます。`main.py` 自体を更新する場合はUSB接続が必要です。実機での更新成功は未検証のため、可能なら先に保存ファイルのバックアップを取ってください。

※海・深海の自動解放はゲーム内の累計進行時間に基づきます。電源OFF中の経過を復元する場合は、スマホの時刻同期と1回最大48時間の復元制限があるため、実際の暦日どおりに解放されない場合があります。

## 🎤 音で変わる世界（マイク実機接続待ち）

ユーザーの画像から外付けモジュールがINMP441であることと6端子の表記を確認しました。**I2Sの読み取りコードは追加済みですが、実機基板の接続先・感度は未確認**のため、初期状態では読み取りを無効にしています。音量値に反応する世界のシミュレーション処理と、スマホ画面のマイク状態表示は接続後に利用できます。

| 世界 | 音への反応 |
| --- | --- |
| 🌿 自然 | 静かなら晴れ、中程度なら風、にぎやかなら雨 |
| 🏘️ 街 | 活気のある音が継続すると住民や建物が少しずつ増える |
| 🌾 共生 | 自然の天候変化と街の発展が両方起こる |
| ✨ 魔法 | 大きな音が魔力になり、複数回の蓄積で珍しい流れ星が現れる |
| 🌲 森 | 音量に応じて晴れ・風・雨が変化する |
| 🐠 水槽 | 音量の変化で波紋や泡のできごとが発生する（実際の音声入力は未接続） |

`firmware/world_model.py` の `engine.observe_sound(level)` に正規化した音量 **0〜100** を約60秒に1回渡す方式です。暫定しきい値は静か `0〜24`、活動中 `25〜69`、にぎやか `70〜100`。**実際のマイクの感度を測って決めた数値ではなく、接続後に調整する初期設定**です。

生音声・会話・録音ファイルは取得・保存しません。各世界の進行カウンターだけを保存し、マイク接続状態は再起動で未接続に戻します。まだ音量値を供給する処理がないため、**現在のファームウェアをそのまま書き込んでも音には反応しません**。外付けモジュールの型番とピン配置を確認してから、I2S／アナログ等の方式に合った読み取り処理を接続します。ピン配置を推測して結線しないでください。

## まずスマホ表示を確認する（ESP32への書き込みなし）

`www/index.html` をPCやスマホのブラウザで開きます。ESP32に接続されていない場合はオレンジ色の **デモ表示** になり、架空の6つの世界を体験できます。これは実機の保存データとは独立しています。

## サンニーの丸形画面

Waveshare ESP32-S3-Touch-LCD-1.28 の内蔵LCDに、スマホ画面と同じシミュレーションから6つの世界を描画します。画面下部の左・右で前・次の世界、景色をタップするとその世界のイベント、水槽の上部をタップすると解放済みの水域を切り替えます。画面の選択は本体とスマホで独立し、世界の進行とイベントは共有します。

時刻同期後は勤務スケジュールに合わせてバックライトが消灯・再点灯します。消灯中も本体は稼働し、Wi-Fiと世界の進行を維持します。ディープスリープは初期値で無効です。電池電圧の警告は、接続した電池をテスターと照合してから `ENABLE_BATTERY_MONITOR` で有効化できます。充電状態の検出は別途、基板から読み取れる信号の確認が必要です。

## ESP32で実際の世界を動かす

1. すでにESP32に別のファームウェアやRadio Roamのデータがある場合は、**先にバックアップ**してください。MicroPythonを書き込むと既存データを消す場合があります。
2. Waveshare公式ドキュメントに沿って、対応するMicroPython環境をセットアップします。MicroPythonのバージョンによって周辺機器のドライバー構成が異なる場合があります。
3. `firmware/settings.py` の `AP_PASSWORD` を8文字以上の**自分だけのパスワード**へ変更し、`ADMIN_KEY` を長く推測されにくい秘密の文字列に変更します。初期値のままでは無線更新は無効です。職場のWi-Fiの利用が許可されていない場合は、`STA_SSID` を空欄にします。
4. Thonnyなどを使い、以下をESP32のファイルシステム直下に転送します。

   - `firmware/*.py` をすべてルートへ転送し、起動する `main.py` を最後に転送
   - `/assets/jp_holidays.json` ← `firmware/assets/jp_holidays.json`
   - `/index.html` ← `www/index.html`

   LCDを先に確認する場合は、`round_lcd.py` を転送し、`mpremote connect COM7 run PocketWorld/tools/lcd_test.py` をリポジトリのルートで実行します。COM番号は対象機器を確認して指定してください。

5. ESP32を再起動します。スマホのWi-Fi一覧で `SANNY-ESP32` を選び、設定したパスワードで接続します。
6. スマホのブラウザで **http://192.168.4.1/** を開きます。
7. 画面右上が緑色の「ESP32に接続中」になれば、ESP32が保持する6世界を表示しています。

**注意:** この接続方式はESP32がWi-Fiを提供するため、スマホは接続中に同じWi-Fi経由のインターネットへは出られません。Androidが「インターネットなし」と表示したら、必要に応じて「このネットワークを使用」を選択してください。職場のネットワークに自動接続する仕組みではありません。

## 専用Androidアプリからサンニーを更新する

同梱の `SannyCompanionAndroid` プロジェクトをAndroid Studioでビルド・インストールします（詳しくは専用README）。

1. アプリの「設定」で `SANNY-ESP32` につなぎ、管理用キーを登録します。
2. 「観察」タブでPocket Worldの6世界を開きます。
3. 「更新」タブからファイルを選択し、アップロードします。
4. `world_model.py` を更新したときは「サンニーを再起動」を実行します。

無線更新の対象は `index.html`、`world_model.py`、`assets/` 以下の `.png` / `.jpg` / `.json` / `.dat` ファイル（1個128KiB以下）です。`main.py`、`settings.py`、MicroPythonファームウェア全体は上書きできません。アップロードした画像は保存されますが、**Pocket Worldの画面に自動反映されるわけではありません**。参照するゲームコードの更新も必要です。

アップロード処理は受信完了後にファイルを差し替え、以前のファイルは同じ場所に `.bak` として保存します。壊れたプログラムによる起動失敗を完全に自動復旧する機能は未実装です。初回導入や復旧時はUSB接続が必要になることがあります。

## 仕組み

- ESP32が6世界の共通状態を管理し、表示中ではない世界も1分ごとに進みます。
- スマホは5秒ごとに `/api/state` を取得して画面を描き直します（ゲーム状態の決定はESP32側）。
- タップすると `/api/touch?world=...` に操作を送ります。
- 約5分ごとにESP32のFlashへ状態を保存し、停電・再起動後も再開します。ただし突然の電源断では、最後の保存以降の進行は失われることがあります。
- スマホと初回接続した際、スマホの現在時刻をもとに最大48時間分まで離席中の進行を推定します。スマホ時刻が誤っていると進行も変わるため、時刻を信用できる状況で使ってください。
- スマホにつながない、かつ時刻同期できない場合は、ESP32の稼働時間の分だけ進みます。電源OFF中の正確な経過時間を完全に再現するには、RTCなどの追加が必要です。
